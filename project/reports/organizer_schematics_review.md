# Схемы АВТ: проверка и первый этап интеграции

Проверены все три одностраничных PDF, включая рукописные теги.
Источник требований: eda/ORGANIZER_QA_UPDATE.md. Обучение моделей не изменялось.

## Технологическая последовательность

- doc00628520260914104632.pdf: ЭЛОУ, подогрев, К-1, Е-1,
  циркуляция через П-1/1, выход в П-1/2 и П-1/3.
- doc00628420260914104535.pdf: К-2, Е-3, отпарные К-6, К-7, К-9,
  отборы бензина, керосина, дизельных фракций, выход мазута.
- doc00628320260914104432.pdf: нагрев мазута в П-3, К-10,
  циркуляционные орошения, вакуумные дистилляты, гудрон.

Это схемы АВТ, а не 24-2000. Названия потоков на схемах не доказывают,
что измеряется конечное товарное дизельное топливо после гидроочистки.
Цвет обводки без легенды не определяет разрешение на управление.

## Подтверждения и расхождения

| Теги | Наблюдение | Ограничение интерпретации |
| --- | --- | --- |
| F30, W70 | Подписи на одной линии ДТ | Единицы и метрология не подтверждены; отношение только proxy |
| F32 | На схеме 240–350 °C | В справочнике 240–290 °C; не заменять автоматически |
| F59, F60 | Подписи у потока 350–560 °C | F59 в справочнике 420–500 °C; принадлежность каждой параллельной линии требует проверки |
| T33 | Низ К-2, выход мазута | Диапазон 50–90 °C в конфигурации не подтверждён схемой |
| T55 | Выход П-3 перед К-10 | Это вакуумная часть АВТ; эффект на качество ДТ не следует из одной схемы |
| F25, F34 | Выходы К-6 и К-7 | Разные продуктовые потоки, не взаимозаменяемые признаки |
| F68, F69 | Линии гудрона | Не дизельный поток |

## Внедрено

- Отдельный реестр process_topology.yaml: аппарат, поток, исходный PDF,
  происхождение diagram_manual_annotation и замечания для проверки.
- API /controls дополняет параметры аннотациями. Для 24-2000 аннотация
  отсутствует: схемы АВТ не переносятся на другую установку.
- В сценариях отображаются аппарат, поток и замечания к диапазону.
- What-if обозначен исследовательской оценкой; причинность не заявляется.
- Не изменены признаки, веса, обучение, шкалы и численные ограничения.

## Следующие этапы, требующие отдельной реализации

1. Диагностика W70/F30: исходное отношение, условный density_proxy_kg_m3,
   контроль стационарности и нулевого расхода. Для robust baseline 7–30 дней
   требуется история соответствующей длины, а не текущий 100-точечный буфер.
2. Разделение режимов normal/startup/shutdown/transition/unknown и политик
   NO_ACTION/ABSTAIN; пороги согласовать по результатам анализа режимов.
3. Отдельная инженерная модель воздействия и экономические сценарии цен.
   Прогнозный регрессор не становится причинным симулятором от подстановки тегов.
4. Валидация ЛИМС по точке отбора и этапу процесса, с раздельными timestamp
   отбора и публикации, если они доступны.
5. Автономная поставка: локальные шрифты, отключение внешних обращений сервисов,
   экспорт фиксированных образов и проверка запуска без сети.

Для агента обучения: использовать аннотации как метаданные групп признаков,
но не менять feature order существующих артефактов и не объявлять importance
причинным эффектом. Вопросы F32/F59/T33 сохраняются открытыми.
